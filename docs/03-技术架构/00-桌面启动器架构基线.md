# 桌面启动器架构基线

更新时间：2026-08-14 23:28（Asia/Shanghai）

## 架构目标

桌面层仅负责 Windows x64、macOS arm64/x64 与 Linux x64 的分发、运行时、子进程、窗口和生命周期；DSH 继续提供 Web UI、Agent、会话和业务能力。

## 运行链路

`Electron 主进程 → 内置 Node 运行时 → DSH 生产入口 → 127.0.0.1 随机端口 → BrowserWindow`

## 运行闭包

- Node 使用官方 Node 24 固定补丁版本并按 Windows x64、macOS arm64/x64、Linux x64 校验 SHA256。
- DSH 使用固定上游 `deepseek-harness` 提交构建，当前候选提交为 `47f943859b`。
- DSH 构建通过 `npm exec --package=pnpm@11.7.0` 使用上游声明的 pnpm；启动器自身构建固定 pnpm 11.20。
- 禁止使用浮动分支、未锁定依赖或 npm 中不存在的 `@deepseek-ai/dsh@0.1.0-rc.5`。
- 运行时文件保留真实文件布局，不将 DSH 依赖临时解压到 ASAR 外。

## 启动与导航

1. Electron 获取单实例锁并展示本地启动页。
2. 以 `dsh web --port 0` 启动 DSH。
3. 缓冲标准输出，识别 `dsh web:` 就绪行。
4. 仅接受 `http:`、`127.0.0.1` 与合法端口的 URL。
5. HTTP 健康检查成功后才加载 BrowserWindow。
6. 失败、超时或异常退出时显示中文错误和脱敏日志位置。

## 安全与生命周期

- Electron 使用 `nodeIntegration: false`、`contextIsolation: true`。
- 禁止任意 Electron IPC 暴露给 DSH 页面。
- 拒绝 `file:`、`javascript:`、`data:` 及非 loopback 导航；外部链接交给系统浏览器。
- 正常关闭通过 Node 引导脚本和父子进程控制通道触发 DSH 既有关闭逻辑。
- 超时只处理启动器创建的 PID；不得全局结束 `node.exe`。
- 不删除 `%USERPROFILE%\.dsh`，日志不得记录敏感数据。
- Linux 窗口关闭即退出；CI 冒烟检查仅为 GitHub Runner 的未安装目录传递 `--no-sandbox`，发布应用保持默认沙箱策略。
