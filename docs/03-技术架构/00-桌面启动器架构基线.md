# 桌面启动器架构基线

更新时间：2026-08-20 01:40（Asia/Shanghai）

## 架构目标

桌面层仅负责 Windows x64、macOS arm64/x64 与 Linux x64 的分发、运行时、子进程、窗口和生命周期；DSH 继续提供 Web UI、Agent、会话和业务能力。

## 运行链路

`Electron 主进程 → 内置 Node 运行时 → DSH 生产入口 → 127.0.0.1 随机端口 → BrowserWindow`

## 运行闭包

- Node 使用官方 Node 24 固定补丁版本并按 Windows x64、macOS arm64/x64、Linux x64 校验 SHA256。
- DSH 运行时从 npm 包 `@deepseek-ai/dsh@0.1.0-rc.8` 在打包时预装到 `runtime-dsh`，首启复制到安装目录下的 `dsh-runtime`；只有安装目录不可写时才回退用户数据目录。
- DSH 构建通过 `npm exec --package=pnpm@11.7.0` 使用上游声明的 pnpm；启动器自身构建固定 pnpm 11.20。
- 官方运行时可随包装一份只读预装树，运行和在线更新写到安装目录旁的可写 `dsh-runtime`；社区插件在线更新写入 `~/.dsh/profiles/web`。Electron 缓存仍在 `%APPDATA%\\DSH Codex Desktop`，卸载时删除，且不得删除 `~/.dsh`。
- 运行时文件保留真实文件布局，不将 DSH 依赖临时解压到 ASAR 外。

## 启动与导航

1. Electron 获取单实例锁并展示本地启动页。
2. 以 `dsh web --port 0 --no-open` 启动 DSH；桌面窗口承载界面，禁止官方 Web 再打开系统浏览器。
3. 缓冲标准输出，识别 `dsh web:` 就绪行。
4. 仅接受 `http:`、`127.0.0.1` 与合法端口的 URL。
5. HTTP 健康检查成功后才加载 BrowserWindow。
6. 失败、超时或异常退出时显示中文错误和脱敏日志位置。

## 安全与生命周期

- Electron 使用 `nodeIntegration: false`、`contextIsolation: true`。
- 禁止任意 Electron IPC 暴露给 DSH 页面。
- 拒绝 `file:`、`javascript:`、`data:` 及非 loopback 导航；外部链接交给系统浏览器。
- 正常关闭通过 Node 引导脚本和父子进程控制通道触发 DSH 既有关闭逻辑。
- 超时只处理启动器创建的 PID；不得全局结束 `node.exe`。
- 不删除 `%USERPROFILE%\.dsh`，日志不得记录敏感数据。
- 卸载只结束 `DSH Codex Desktop.exe` 及其子进程，必须排除 `Uninstall*`，不得按安装目录无差别杀进程；完成后删除 `%APPDATA%\\DSH Codex Desktop` 与托盘 `NotifyIconSettings` 残留。
- Linux 窗口关闭即退出；CI 冒烟检查仅为 GitHub Runner 的未安装目录传递 `--no-sandbox`，发布应用保持默认沙箱策略。
- 桌面 exe 更新只走托盘「检查桌面端更新」，源是 GitHub Releases 的 latest.yml；启动不检查、不自动下载。插件更新仍走关于页，二者不得混用。


## 社区插件随包与在线安装

- 六个社区包在 `prepare-runtime` 写入 `runtime-plugins/store.tgz`，打包成单个压缩包，避免安装器解压上万个小文件。
- 首次启动用离线 store 把社区插件补种到 `~/.dsh/profiles/web`。
- 已装 `@michengai/dsh-codex-suite` 时拆成六个独立插件；已有同名包时跳过，不覆盖用户在线安装的版本。
- 解析顺序是安装目录优先，因此社区包不得进入官方运行时 `node_modules`。
- 随包 `resources/node` 同时提供 `node` 与 `pnpm`；DSH 子进程 PATH 前置该目录，code-ui 与 dshmarket 的 CLI 安装路径才能工作。
- 补种失败只写 `plugin-seed.log`，不阻断 DSH 启动。

## 官方运行时预装

- `prepare-runtime` 把 `@deepseek-ai/dsh` 和启动必需 peer 预装后打成 `runtime-dsh.tgz`，首启再解到安装目录。
- 官方 DSH 家族统一锁 `0.1.0-rc.8`，并通过 `pnpm.overrides` 钉死 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*`，避免 `^` 范围把子包装到一半。
- 首启复制到安装目录 `dsh-runtime`；复制失败才回退现场安装。启动时不再查官方版本，也不自动升级。
- 官方包不得写入 Web profile。关于页、插件市场若更新 `@deepseek-ai/dsh*`，桌面端改写 `dsh-runtime` 整组版本，不把官方包装进用户 profile。
- 官方运行时只在关于页手动点更新时整组升级；点了才写 pending，并由桌面端改 `dsh-runtime`。
- 安装包会变大，换来的是新用户首启不再解析、下载、链接整棵官方依赖。
