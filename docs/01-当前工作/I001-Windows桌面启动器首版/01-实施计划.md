# I001 实施计划

更新时间：2026-08-14 14:01（Asia/Shanghai）

## 阶段一：运行闭包闸门

1. 更新本地 `origin` 为 MichengAI 规范地址，不自动推送。
2. 固定上游提交、Node 24 补丁版本、SHA256 和 lockfile。
3. 复用上游生产构建，组装最小运行闭包。
4. 在隔离目录中用内置 Node 运行 `dsh web --port 0`。
5. 验证 HTTP 200、前端资源、Windows 原生依赖和关闭后无残留进程。

通过后才能进入阶段二。

## 阶段二：测试先行的进程模块

- 先编写输出分片、非法 URL、启动超时、提前退出、重复关闭的失败测试。
- 实现 `src\readiness.ts`、`src\dsh-process.ts` 与 `runtime\bootstrap.mjs`。
- 每个模块保留最小可运行检查。

## 阶段三：桌面壳与打包

- 实现 `src\main.ts`、本地启动页、单实例、托盘与安全导航。
- 选择单一打包工具生成 ZIP、当前用户安装器和 SHA256。
- 在 Windows CI 执行打包后启动、HTTP 200 和关闭无残留的冒烟。

## 回滚

- 不修改 DSH 上游；桌面提交可独立回退。
- 运行时版本问题回退固定 Node 或上游提交后重新构建。
- 不删除用户 `%USERPROFILE%\.dsh` 数据。
