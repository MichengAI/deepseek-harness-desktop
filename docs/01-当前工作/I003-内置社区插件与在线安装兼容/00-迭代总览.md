## 目标与业务边界

把六个功能插件与 dshmarket 装进桌面安装包，首启写入用户 Web profile。在线安装和更新继续走 `dsh plugin add`。社区插件不得进入 DSH 安装目录 `node_modules`，否则安装目录优先解析会挡住 profile 里的新版本。

## 验收标准

- 新用户首次启动后，Web profile 含六个功能插件与 dshmarket，或存在明确的补种失败日志
- 已装 `@michengai/dsh-codex-suite` 时不重复写入子插件
- 打包应用的 `resources\\node` 可执行 `pnpm --version`
- code-ui / dshmarket 的 `dsh plugin add` 仍写入 `~/.dsh/profiles/web`
- 安装器可选目录，选完后路径自动带上 `dsh-codex-desktop`
- DSH 缺 peer 时能自动补齐并写出完整启动日志
- 窗口默认最大化
- 新安装包首启从 `resources\\dsh-runtime.tgz` 原子解压到可写目录，不再现场安装整棵官方依赖
- Windows 与 macOS 双架构更新元数据都指向 Release 中的真实资产
- desktop-bridge 独立目录可完成 ESM 导入
